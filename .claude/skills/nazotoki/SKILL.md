# 謎解きイベントの作り方（全体像）

参加者が現地を回り、問題に答え、正解を集める。それを T&T の world で成立させるための仕組みと、
作る前に決めることをまとめる。

world の一般的な操作（`create` → `update` の2段階、アイテム関連の全置換、ページネーション）は
**`ttt-world-building` スキルが持っている**。このスキルは謎解き固有の部分だけを扱う。

## 仕組み

```
受付イベント ──→ 回答券を N 枚配る
                      │
問題ごとに選択肢の数だけイベントを作る
  ├ 正解のイベント  ── 回答券1枚を消費 ──→ 正解の印を1つ渡す
  └ 不正解のイベント ── 回答券1枚を消費 ──→ 何も渡さない
```

参加者は、各イベントのURLをQRコードで読んでチェックインする。

**回答券が問題数と同じ枚数しか手に入らないことが、この仕組みの要**。
たとえば9問×3択なら選択肢は27個あるが、回答券は9枚しかないので総当たりできない。
1問につき1回しか答えられず、外すとその問題を失う。

この性質から、**守るべき秘密は受付イベントのURL**になる。回答用のページやQRが知られても、
回答券がなければ答えられない。受付のURLは印刷物など現物にだけ載せ、ウェブサイトには置かない。

## 決めること

### 1. 問題数と選択肢数

どちらも自由に決められる。イベント件数がそれで決まる。

```
イベント数 = 1（受付） + 問題数 × 選択肢数
```

**ベーシックプラン（無料）はイベント10件まで**。アイテムは無制限で、制限があるのはイベントだけ。
10件でどこまで作れるかを、最初に見せて選んでもらう。

| 構成 | 件数 | 向く企画 |
|---|---|---|
| **4問 × 2択（○×）** | 9 | **初めて作る人に勧める**。作問が軽く、地点が4つになる |
| **3問 × 3択** | 10 | 三択の歯ごたえがほしいとき |
| 9問 × 3択 | 28 | 有料プラン。本格開催の規模 |

初めて作る人には **4問 × 2択（○×）** を勧めるとよい。○×は選択肢のダミーを考える必要がなく、
作問の負荷が大きく下がる。地点が4つになるので周遊としても成立する。

### 2. 何個集めたら達成とするか

印が何個あるかは、参加者の持ち物として見える。店頭で見せてもらえば、景品を渡す基準になる。
これは world の設定ではなく**運用の取り決め**なので、決めておくだけでよい。

**満点にしない。** 1問につき1回しか答えられないので、満点を条件にすると達成者がほとんど出ない。
**問題数の 2/3 くらい**が目安（9問なら6個、4問なら3個）。

参考までに、全問を当てずっぽうで答えたときの達成率はこのくらいになる。

| 構成 | 達成ライン | 当てずっぽうでの達成率 |
|---|---|---|
| 4問 × 2択 | 3問以上 | 31% |
| 3問 × 3択 | 2問以上 | 26% |

選択肢が少ないぶんは、クリア条件を厳しくすれば吸収できる。**○×だから運任せで通る、とは限らない**。

## 作問で守ること

謎解きの目的は、**難しさではなく、人が移動すること**。それを壊さないための最低限だけ挙げる。

1. **1問につき1回しか答えられない。** だから「考えれば分かる」に寄せる。運任せの問題にしない
2. **選択肢は現地で手に入れさせる。** 問題文だけで解けなくてよい。掲示や現物と照合させると、
   選択肢が「問題の一部」ではなく「現地に行く理由」になる
3. **明らかな外れを作らない。** 1つでも捨てられると、三択が実質二択になる
4. **時間が経っても失われないものをヒントにする。** 石碑や建物、地名のように、簡単には変わらないものを選ぶ。
   掲示物1枚や植栽1本に頼ると、開催期間の途中で失われて問題が死ぬ
5. **掲示できるかを、作る前に確認する。** 選択肢を置けない場所では問題が成立しない

## Claude にできないこと

この仕組みで自動化できるのは world の設定だけ。**現地は人間の仕事**で、しかもそこが一番重い。

| 段階 | 誰が |
|---|---|
| 現地調査（掲示可否の確認を含む） | **人間のみ。作問より先に行う** |
| 答えの選定 | Claude が候補を出し、人間が現地で裏取り |
| 作問・解説文 | Claude 主体 |
| **現地テスト**（答えを知らない人に解いてもらう） | **人間のみ** |
| world の構築 | Claude（`nazotoki-setup`） |
| 配線の検証 | Claude（`nazotoki-check`） |
| 印刷・掲示 | **人間のみ** |

作業を始める前に、この表を見せて「現地調査は済んでいますか」を確認する。
済んでいないのに作問から入ると、掲示できない場所に選択肢を置いてしまい、後から全部やり直しになる。

## 進め方

1. 構成を決める（上の表を見せて選んでもらう）
2. `flavor.json` を選ぶか書く（世界観。回答券と印の名前・文言）
3. `event.json` を書く（正解表と解説。**問題文と選択肢の文言は書かない**）
4. **`nazotoki-setup`** で world を構築する
5. **`nazotoki-check`** で配線を検証する
6. 各イベントのURLをQRにして印刷する（人間）

データ形式の詳細は、このスキルに同梱の `references/data-format.md` にある。ひな形として、世界観なしの `assets/flavor/plain/flavor.json` と、無料枠に収まる○×クイズ（受付1＋4問×2択＝9件）の `assets/examples/free-4x2/event.json` を同梱している。

デジタルの記念品を配りたい場合は、**印を N 個持っていることを条件にしたイベントを1件、
自分で作る**（`ttt-world-building` スキル）。1件だけなので、キットで自動化する対象にしていない。

## 回答用のページについて

参加者に選択肢を選ばせる方法は3段階ある。**最初は段階1で十分**。

| 段階 | 方法 | 要るもの |
|---|---|---|
| **1** | 問題シートに選択肢の数だけQRを直接印刷する | **なし** |
| 2 | 静的ホスティングに回答ページを置く | GitHub など |
| 3 | 独自ドメインで回答ページを運用する | ドメイン・CDN |

**サイトを作らなくても謎解きは成立する**。段階1なら、ドメインもホスティングも要らずに最後まで到達できる。
あとから段階2・3へ上げられる。

段階1で印刷するときは、QRの横に「問題1 ○」のようなラベルだけを添える。
**選択肢の中身は絶対に印字しない**。それ自体がヒントになる。
