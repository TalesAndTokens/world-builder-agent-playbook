# 謎解き world の検証

作った構成が意図どおりに配線されているかを、**読み取りだけ**で確認する。
このスキルは world を変更しない。直すべき点が見つかったら、内容を報告して指示を仰ぐ。

`ttt-world-building` のページネーション規約に従い、`list_events` / `list_items` は
件数が `perPage` 未満になるまで `cursor` を進めて全件取得する。

## なぜ必要か

この仕組みは、**正解の印を1種類だけ作り、その個数でクリアを判定する**。
だから配線を1件間違えるだけで、企画全体が壊れる。

- 不正解のイベントに印を付けてしまうと、**そこを踏んだ全員がクリアできる**
- 正解のイベントに印を付け忘れると、**その問題は正解しても進まない**

どちらも参加者が現地にいるときに発覚し、印刷物は配り終えている。**公開前にしか直せない。**

## 検査の対象を分ける

world には、キットが作る基本のイベントのほかに、応用で足したイベントがありうる（`nazotoki` スキルの「応用」）。
**検査の前に、全イベントを次の3つに分ける。** 分けずに検査すると、応用のイベントを誤って NG にする。

| 区分 | 見分け方 | 例 |
|---|---|---|
| 受付 | 回答券を出し、何も消費しない | `受付` |
| 回答イベント | 名前が `問題N　答えX` で、**X が `choiceLabels` のどれか** | `問題3　答えB` |
| 応用のイベント | 上のどちらでもないもの | `問題3　カノリのヒント`（ヒント）、記念品のイベント、テスト用の受付 |

名前に「問題N」が入っていても、`答えX` の形でなければ回答イベントに数えない（ヒントのイベントを問題数に混ぜない）。
テスト用の受付（何度でも受け取れる・どこにもリンクしない）は、本番の受付と区別して報告する。

## 検査項目

数の検査から先に行う。合わないものが1つでもあれば、それ以降の検査より優先して報告する。

### 1. 印を出すイベントの数 ＝ 問題数（最重要）

全イベントの `outputItems` を調べ、印を1つ以上出すものを数える（応用のイベントも含めて数える。ヒントや記念品のイベントが印を出していたら、それも NG）。
**問題数とちょうど一致しなければならない。**

- 多い → 不正解のイベントに印が付いている
- 少ない → 正解のイベントで印を付け忘れている

`問題N　答えX` という名前から問題番号を取り、**1問につき印を出すイベントがちょうど1つ**
あることまで確認する。総数が合っていても、ある問題に2つ、別の問題に0、という偏りがありうる。

### 2. 回答イベントの数 ＝ 問題数 × 選択肢数

抜けがあると、その選択肢を選んだ参加者が行き止まりになる。

### 3. 受付が配る回答券の枚数 ＝ 問題数

少ないと最後まで答えられない。多いと総当たりできてしまい、この仕組みの前提が崩れる。
**問題を後から追加したときに最も壊れやすい箇所**なので、必ず見る。

### 4. 回答イベントはすべて回答券を1枚消費するか

`inputItems` に回答券が1つ入っているか。抜けていると、そのイベントだけ何度でも試せる。

### 5. 不正解のイベントが印を出していないか

1の裏返しだが、イベント単位で明示的に確認して報告する。

不正解のイベントが**印以外のもの**を出すのは、応用の「救済」なら正しい（回答券を1枚返す、ヒントに使う相棒を渡す）。
NG にせず、どのイベントが何を出しているかを一覧で報告する。ただし次は NG。

- 不正解のイベントが**回答券を2枚以上**返している（使うより多く返すと、回数の制限が壊れる）
- 回答券を返す不正解のイベントの `checkinLimitPerUser` が1でない（何度でも踏んで回答券を増やせる）

### 6. `endPeriod` が全イベントに入っているか

1件でも抜けると、**その問題だけ会期後も答えられる**。受付も含めて全件を見る。

### 7. `checkinLimitPerUser` が 1 か

**受付と回答イベントについて**確認する。0（無制限）だと、同じ選択肢を何度も試せてしまう。

応用のイベントは、決まりが違うので別に見る。

- **ヒントのイベント**：0（何回でも）でよい。ヒントは画面を閉じると読み返せないので、もう1回分を払えば聞き直せるようにしている。そのかわり、**ヒント用のアイテム（相棒など）を1つ消費する**こと（`inputItems`）と、**印を出さない**ことを確認する。消費が抜けていると、誰でも無料で何度でもヒントを見られる
- **テスト用の受付**：0でよいが、URL がウェブや印刷物に出ていないことを検査8で確かめる

### 8. 受付イベントのURLが漏れていないか

回答用のウェブページを作っている場合、その中に**受付イベントのURLが含まれていないか**を確認する。
受付URLは回答券が手に入る入口で、これが公開されると誰でも回答券を得られる。
`sitemap.xml` や公開ページからのリンクも見る。テスト用の受付のURLも同じ扱い。

## 報告のしかた

結果は表で出し、**落ちた項目を先に**書く。全部通ったときもその旨を明示する。

```
検査項目                          結果
--------------------------------  --------
印を出すイベントの数 = 問題数      NG  10件（問題数は9）
  └ 問題4に2件（答えA・答えB）
回答イベントの数                   OK  27件
受付が配る回答券                   OK  9枚
endPeriod の設定                   NG  問題7 答えC が未設定
...
```

落ちた項目については、**どのイベントのどの設定をどう直すか**まで具体的に書く。
直すのは `nazotoki-setup` か `ttt-world-building` の操作になるので、
指示を受けてから実行する。
